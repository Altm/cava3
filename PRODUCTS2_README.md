# Продукты 2 — Улучшенный интерфейс управления продуктами

## Обзор

**Продукты 2** — это современный интерфейс для управления продуктами с полной поддержкой:
- Дробных единиц измерения (бокалы, ломтики, мл и т.д.)
- Составных продуктов (рецепты, наборы)
- Рекурсивных композиций (продукт в продукте)
- Продажи по бокалам (wine by glass)

## Доступ к интерфейсу

Откройте в браузере: `http://your-domain.com/products2`

## Основные возможности

### 1. Список продуктов (ProductListView2)

**URL:** `/products2`

**Функции:**
- Современная таблица с фильтрами
- Поиск по названию с автодополнением
- Фильтры по локации, типу продукта, составности
- Отображение дробных единиц
- Быстрые действия (просмотр, редактирование, удаление)

**Примеры использования:**
```
Фильтры:
- Локация: Main Warehouse
- Тип продукта: Вино
- Составной: Нет
- Единица: bottle
```

### 2. Создание/Редактирование продукта (ProductForm2)

**URL:** 
- Создание: `/products2/create`
- Редактирование: `/products2/{id}/edit`

**Основные поля:**

#### Основная информация
- **Тип продукта** — выбирается из справочника (определяет атрибуты и единицы)
- **Название** — отображаемое имя продукта
- **SKU** — артикул для поиска
- **Базовая стоимость** — цена за базовую единицу
- **Базовая единица** — основная единица измерения (кг, бутылка, штука)

#### Атрибуты
Атрибуты определяются типом продукта:
- **Числовые** (volume, weight, strength)
- **Булевы** (has_pit, is_organic)
- **Строковые** (color, region)

#### Дробные единицы
Для продажи продукта в разных единицах:

**Пример для вина:**
```
Базовая единица: bottle (1.0)
Дробные единицы:
- glass: 0.1667 (1/6 бутылки)
- pour: 0.0833 (1/12 бутылки, 125мл от 750мл)
```

**Пример для хлеба:**
```
Базовая единица: kg (1.0)
Дробные единицы:
- slice: 0.05 (50г)
- loaf: 0.4 (400г буханка)
```

**Пример для томатной пасты:**
```
Базовая единица: kg (1.0)
Дробные единицы:
- gram: 0.001 (1г)
- tube: 0.05 (50г тюбик)
```

#### Компоненты (для составных продуктов)
Для создания рецептов и наборов:

**Пример "Бутерброд":**
```
Тип продукта: Бутерброд (Составной)
Базовая единица: piece

Компоненты:
1. Багет: 0.1 кг (100г ломтик)
2. Томатная паста: 0.02 кг (20г)
```

**Пример "Дегустационный набор":**
```
Тип продукта: Дегустационный набор (Составной)
Базовая единица: piece

Компоненты:
1. Красное вино: 0.167 бутылки (1/6 бутылки = 1 бокал)
2. Белое вино: 0.167 бутылки
3. Розовое вино: 0.167 бутылки
4. Бутерброд: 1 piece
```

### 3. Детальный просмотр (ProductView2)

**URL:** `/products2/{id}`

**Отображаемая информация:**

#### Основная карточка
- Изображение продукта
- Название и SKU
- Тип продукта
- Базовая стоимость и остаток
- Базовая единица

#### Дробные единицы
Таблица со всеми единицами измерения:
- Единица и код
- Тип (базовая, упаковка, порция)
- Ratio к базовой
- Цена за единицу (рассчитывается автоматически)
- Количество в базовой

#### Дерево компонентов
Для составных продуктов показывает рекурсивную структуру:
```
Дегустационный набор
├── Красное вино (0.167 bottle)
├── Белое вино (0.167 bottle)
├── Розовое вино (0.167 bottle)
└── Бутерброд (1 piece)
    ├── Багет (0.1 kg)
    └── Томатная паста (0.02 kg)
```

#### Примеры использования
Система автоматически показывает:
- Продажа в базовых единицах
- Продажа в дробных единицах
- Использование как компонента в других продуктах

#### Остатки по локациям
Для каждого склада/магазина:
- Базовое количество
- Отображаемое количество
- Разбивка по единицам измерения

## API Endpoints

### Продукты
```
GET    /api/v1/products2/                      # Список продуктов
GET    /api/v1/products2/count                 # Количество продуктов
GET    /api/v1/products2/{id}                  # Продукт

POST   /api/v1/products2/                      # Создать продукт
PUT    /api/v1/products2/{id}                  # Обновить продукт
DELETE /api/v1/products2/{id}                  # Удалить продукт
POST   /api/v1/products2/{id}/image            # Загрузить изображение
```

```
GET    /api/v1/products2/{id}/fractional-units       # Список единиц
POST   /api/v1/products2/{id}/fractional-units       # Добавить единицу
PUT    /api/v1/products2/{id}/fractional-units/{uid} # Обновить единицу
DELETE /api/v1/products2/{id}/fractional-units/{uid} # Удалить единицу
```

### Компоненты
```
GET    /api/v1/products2/{id}/components             # Список компонентов
POST   /api/v1/products2/{id}/components             # Добавить компонент
PUT    /api/v1/products2/{id}/components/{cid}       # Обновить компонент
DELETE /api/v1/products2/{id}/components/{cid}       # Удалить компонент
```

### Дерево компонентов
```
GET    /api/v1/products2/{id}/component-tree         # Рекурсивное дерево
GET    /api/v1/products2/{id}/usage-examples         # Примеры использования
```

## Продажа дробных единиц

### Продажа бокалами вина

**Endpoint:** `POST /api/v1/simple-catalog/sales/checkout`

```json
{
  "lines": [
    {
      "kind": "glass",
      "productId": 1,
      "quantity": 2,
      "unitId": 6
    }
  ]
}
```

**Логика:**
1. Система находит бутылку с наибольшим количеством непроданных бокалов
2. Создаётся запись `ProductItemPour` с `glasses_total=6`, `glasses_sold=2`
3. Списание stock: `quantity = -2 * 0.1667 = -0.3334` бутылки
4. При продаже всех 6 бокалов бутылка помечается как проданная

### Продажа составного продукта

```json
{
  "lines": [
    {
      "kind": "product",
      "productId": 12,
      "quantity": 1,
      "unitId": 3
    }
  ]
}
```

**Логика:**
1. Система рекурсивно раскрывает состав бутерброда
2. Списывает компоненты:
   - Багет: `-0.1 kg`
   - Томатная паста: `-0.02 kg`
3. Если компонент сам составной — раскрывает дальше

## Типы единиц (Unit Types)

| Тип | Описание | Пример |
|-----|----------|--------|
| `base` | Базовая единица продукта | kg, bottle, piece |
| `package` | Упаковочная единица | box, case |
| `portion` | Порционная единица | glass, slice, pour |

## Строгий режим единиц

Если у типа продукта установлен флаг `strictUnitsByType=true`, то:
- Разрешены только единицы, определённые в типе продукта
- Нельзя добавить произвольную единицу
- Базовая единица всегда разрешена

**Пример:**
```
Тип продукта: Вино
Строгий режим: Да
Разрешённые единицы:
- bottle (базовая)
- glass
- pour

Нельзя добавить: kg, liter
```

## Советы по использованию

### 1. Планирование структуры продуктов

Перед созданием продуктов определите:
- Какие продукты будут простыми, какие составными
- Какие единицы измерения нужны для каждого типа
- Какие атрибуты требуются для учёта

### 2. Настройка дробных единиц

**Для вина:**
- Установите `glasses_per_bottle` в атрибутах продукта
- Добавьте единицу `glass` с `ratio_to_base = 1 / glasses_per_bottle`
- Установите `discrete_step = 1` для продажи целыми бокалами

**Для хлеба:**
- Добавьте `slice` с `ratio_to_base = 0.05` (50г от 1кг)
- Добавьте `loaf` с `ratio_to_base = 0.4` (400г буханка)

### 3. Создание составных продуктов

**Рецепты (Бутерброд):**
- Указывайте точные количества компонентов
- Используйте те же единицы, в которых ведётся учёт
- Проверяйте доступность компонентов перед продажей

**Наборы (Дегустационный сет):**
- Можно включать другие составные продукты
- Система автоматически раскроет рекурсивную структуру
- Проверяйте циклы (продукт не может включать сам себя)

### 4. Контроль остатков

- Настройте минимальные остатки для компонентов
- Используйте фильтры для поиска продуктов с низким остатком
- Проверяйте дерево компонентов перед запуском акций

## Устранение проблем

### Ошибка: "Composite cycle detected"

**Причина:** Продукт включает сам себя через цепочку компонентов.

**Решение:**
1. Откройте дерево компонентов
2. Найдите цикл (продукт → ... → продукт)
3. Удалите лишний компонент

### Ошибка: "Insufficient stock for component"

**Причина:** Недостаточно компонента на складе.

**Решение:**
1. Проверьте остатки компонента
2. Пополните склад
3. Или уменьшите количество компонента в рецепте

### Ошибка: "Unit already bound to product"

**Причина:** Единица уже добавлена к продукту.

**Решение:**
1. Проверьте список единиц продукта
2. Обновите существующую единицу вместо добавления новой

## Миграция со старых продуктов

Старые продукты (`/product-list`) и новые (`/products2`) используют одну базу данных.

**Рекомендации:**
1. Постепенно переносите продукты в новый интерфейс
2. Проверяйте дробные единицы после переноса
3. Тестируйте продажу составных продуктов

## Поддержка

При возникновении проблем:
1. Проверьте логи backend (`/api/v1/products2/...`)
2. Проверьте консоль браузера (F12)
3. Убедитесь, что у пользователя есть права `product.read` / `product.write`
