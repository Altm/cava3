## Общая информация

### Назначение системы

**Cavina 3** — это комплексная система управления складом, инвентаризацией и продажами для ресторанов и розничной торговли алкоголем.

### Ключевые возможности

- ✅ **Серийный учёт** — отслеживание каждой единицы товара (бутылки) по QR-кодам
- ✅ **Упаковка в коробки** — группировка товаров для удобного перемещения
- ✅ **Перемещения между локациями** — склад → бар с подбором по FIFO
- ✅ **Инвентаризация** — сверка фактического остатка с учётным
- ✅ **Продажи** — единый интерфейс для всех типов продаж
- ✅ **Дробные единицы** — продажа бокалами, ломтиками, порциями
- ✅ **Составные товары** — рецепты, наборы, рекурсивная декомпозиция
- ✅ **Версионирование прайсов** — история изменений цен с расчётными алгоритмами

### Технологический стек

| Компонент | Технология |
|-----------|------------|
| Backend | Python 3.11+, FastAPI, SQLAlchemy |
| Frontend | React, TypeScript, Vite |

```
receiving → in_stock → in_transit → received
    ↓           ↓           ↓
  voided     sold        lost
```

## Приёмка (QR)

### Назначение

Процесс поступления товаров на склад с созданием партий и сериализованных единиц.

### Как работает

```
1. Выбор склада (локации)
         ↓
2. Создание документа приёмки
         ↓
3. Добавление строк: товар + количество + номер партии
         ↓
4. Генерация → создание lot и product_item
         ↓
5. Печать этикеток ITM
         ↓
6. (Опционально) Упаковка в коробки
         ↓
7. Подтверждение → товары на складе
```

### Автоматическая упаковка в коробки

**Поля формы:**

| Поле | Назначение |
|------|------------|
| Количество в коробке | Сколько item в одну коробку |
| Лимит коробок | Ограничение на количество коробок за запуск |
| Товар | Упаковывать только выбранный товар |
| Lot ID | Упаковывать только выбранную партию |
| Создавать неполную коробку | Разрешить коробку с остатком |
| Полные коробки закрывать | Seal полные коробки |

**Пример многоэтапной упаковки:**

```
Запуск 1: 12 бутылок/коробка, лимит 10 коробок
Запуск 2: 6 бутылок/коробка для остатка
Запуск 3: 1 бутылка/коробка с неполной коробкой
```

## Перемещение (QR)

### Назначение

Перемещение товаров между локациями (склад → бар) с подбором по FIFO.

### Как работает

```
1. Создание документа: склад → бар
         ↓
2. Формирование списка (FIFO)
   - Сначала sealed коробки (если подходят)
   - Затем поштучно FIFO (старые UUID)
         ↓
3. Корректировка списка
   - Удаление лишних позиций
   - Добавление по скану ITM
         ↓
4. Отбор на складе
   - Скан ITM → in_transit
   - Скан BOX (sealed) → все товары
   - Частичная отгрузка → авто-открытие коробки
         ↓
5. Отгрузка
         ↓
6. Приёмка в баре (скан ITM/BOX)
         ↓
7. Закрытие
   - Непринятые → lost_in_transit
```

### Особенности

- **Частичная отгрузка из sealed коробки**: коробка автоматически открывается, нужные товары выводятся
- **FIFO подбор**: приоритет у самых старых UUID товаров
- **Коробки разного размера**: поддерживаются через многократный запуск автоупаковки

## Инвентаризация (QR)

### Назначение

Сверка фактического наличия товаров в локации с учётным.

### Как работает

```
1. Выбор локации
         ↓
2. Создание документа → Старт
   - Формирование ожидаемого списка
         ↓
3. Сканирование на месте
   - ITM → конкретная бутылка
   - BOX (sealed) → все товары в коробке
         ↓
4. Закрытие
   - Ненайденные → lost (reason: missing_inventory)
```

## Дробные единицы измерения

### Назначение

Продажа товаров в различных единицах (бокалы, ломтики, мл).

### Типы единиц

| Тип | Описание | Пример |
|-----|----------|--------|
| `base` | Базовая единица | bottle, kg, piece |
| `package` | Упаковочная единица | box, case |
| `portion` | Порционная единица | glass, slice, pour |

### Примеры настройки

**Вино:**
```
Базовая единица: bottle (1.0)
Дробные единицы:
- glass: 0.1667 (1/6 бутылки)
- pour: 0.0833 (1/12 бутылки, 125мл от 750мл)
```

**Хлеб:**
```
Базовая единица: kg (1.0)
Дробные единицы:
- slice: 0.05 (50г)
- loaf: 0.4 (400г буханка)
```

**Томатная паста:**
```
Базовая единица: kg (1.0)
Дробные единицы:
- gram: 0.001 (1г)
- tube: 0.05 (50г тюбик)
```

### Строгий режим единиц

Если `strictUnitsByType=true`:
- Разрешены только единицы из типа продукта
- Базовая единица всегда разрешена
- Нельзя добавить произвольную единицу

## Составные товары

### Назначение

Создание рецептов и наборов из нескольких компонентов.

### Пример 1: Бутерброд

```
Тип: Составной
Базовая единица: piece

Компоненты:
- Багет: 0.1 kg (100г ломтик)
- Томатная паста: 0.02 kg (20г)
```

### Пример 2: Дегустационный набор (рекурсивный)

```
Тип: Составной
Базовая единица: piece

Компоненты:
- Красное вино: 0.167 bottle
- Белое вино: 0.167 bottle
- Розовое вино: 0.167 bottle
- Бутерброд: 1 piece
    ├── Багет: 0.1 kg
    └── Томатная паста: 0.02 kg
```

### Версионирование рецептов

**Таблицы:**
- `product_recipe` — заголовок версии рецепта
- `product_recipe_component` — компоненты версии

**Как работает:**
- При изменении состава создаётся новая версия
- Старая версия закрывается (`valid_to`)
- Текущий срез остаётся в `product_composite`

### Waste Factor

Для компонентов можно задать коэффициент потерь:

```
Эффективный расход = quantity * (1 + waste_factor)
```

**Пример:**
```
Томатная паста: 0.02 kg, waste_factor = 0.1
Эффективный расход = 0.02 * 1.1 = 0.022 kg
```

## Продажи

### Единый интерфейс checkout

**Endpoint:** `POST /api/v1/simple-catalog/sales/checkout`

### Способы добавления в корзину

| Способ | Описание | Пример |
|--------|----------|--------|
| По товару | Товар + количество + юнит | Вино, 2 bottle |
| По QR единицы | Конкретный item | `ITM:...` |
| По QR коробки | Целая коробка | `BOX:...` |
| По бокалам | Товар + количество бокалов | Вино, 3 glass |

### Как работает checkout

```
1. Добавление позиций в корзину
         ↓
2. Оформление продажи
         ↓
3. Система:
   - Списывает агрегированный остаток
   - Списывает конкретные product_item
   - Обновляет состояние коробок (quantity)
   - Отправляет в /api/v1/sales/register-sales-transactions
         ↓
4. Возврат итога с расшифровкой
```

### Правила для бокалов

- Если передан `item_qr_code` → списание с конкретного item
- Если не передан → первый доступный item по FIFO
- При исчерпании бутылки → item переводится в `sold`

### ProductItemPour

**Таблица для учёта бокалов:**

| Поле | Назначение |
|------|------------|
| `product_item_id` | Ссылка на конкретный item |
| `glasses_total` | Сколько бокалов в полной бутылке |
| `glasses_sold` | Сколько бокалов продано |

### ProductItemUsage

**Обобщённый учёт частичного списания:**

| Поле | Назначение |
|------|------------|
| `product_item_id` | Ссылка на item |
| `total_units` | Всего единиц (бокалов) |
| `used_units` | Использовано единиц |
| `unit_id` | Единица измерения |
| `metadata_json` | Дополнительные данные |

## Управление прайсами

### Назначение

Формирование цен для локаций с историей изменений и расчётными алгоритмами.

### Как работает

```
1. Выбор локации
         ↓
2. Создание ревизии (режимы):
   - Процент на все товары (+5%)
   - Фиксированная добавка (+10)
   - Версионированный расчёт (calculator)
         ↓
3. Применение к price_list
         ↓
4. Сохранение истории:
   - price_list_revision
   - price_list_revision_item
```

### Версии расчётов

**Структура:**

| Таблица | Назначение |
|---------|------------|
| `price_calculator` | Реестр расчётов (code, name, description) |
| `price_calculator_version` | Версии реализаций (version, file_path, class_name) |

**Примеры версий:**

```
example_multiplier.py → Example Multiplier, v1.0.0
example_multiplier_v2.py → Example Multiplier, v1.1.0 (добавлен floor)
```

### Расширение price_list_revision

| Поле | Назначение |
|------|------------|
| `calculator_version_id` | Ссылка на версию расчёта |
| `calculator_name_snapshot` | Имя на момент пересчёта |
| `calculator_version_snapshot` | Версия на момент пересчёта |
| `calculator_source_hash_snapshot` | Hash исходника (SHA256) |

### Runtime Flow

```
1. GET /prices/calculators
   - Синхронизация версий из файлов в БД
         ↓
2. POST /prices/revisions (mode=calculator)
   - Использование calculator_version_id
   - Fallback по file + class (для старых версий)
         ↓
3. Сохранение снапшота метаданных
```

### Важные правила

- Прайс создаётся только для товаров с остатком (`stock.quantity > 0`)
- При запросе текущего прайса → последняя ревизия
- Если ревизий нет → текущие строки `price_list` (только товары в наличии)
- Валидация JSON параметров на фронте с понятной ошибкой
