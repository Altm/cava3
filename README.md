# Порядок действий (QR)

Ниже описаны рабочие процессы для новых разделов меню: **Приёмка (QR)**, **Перемещение (QR)**, **Инвентаризация (QR)**.  
Во всех процессах **QR содержит только тип и UUID** (`ITM:{uuid}`, `BOX:{uuid}`), все связи — по `id`.

---

## Приёмка (QR)

1. Откройте **Приёмка (QR)** и выберите склад (локацию).
2. Нажмите **Создать** — создаётся документ приёмки.
3. Добавьте строку: **товар + количество** (базовая единица).  
   Дополнительно можно указать номер партии поставщика.
4. Нажмите **Сгенерировать** — создаются **партия (lot)** и **единицы товара (product_item)**.
5. Нажмите **Печать этикеток ITM** — распечатайте и наклейте QR на бутылки.
6. (Опционально) Сформируйте коробки вручную:
   - Отсканируйте любую бутылку `ITM:...` для контекста (product/lot/location).
   - Нажмите **Создать коробку** (создаётся открытая коробка).
   - Сканируйте `ITM:...` и добавляйте товары в коробку.
   - Нажмите **Закрыть (seal)** и распечатайте QR коробки (**QR коробки**).
7. (Опционально) Сформируйте коробки автоматически в блоке **Автоматическая упаковка в коробки**.
8. Нажмите **Подтвердить** — приёмка зафиксирована.  
   **Отменить** — погасит сгенерированные единицы (void).

---

## Перемещение (QR)

> Механика похожа на приёмку, **но партия не создаётся**.

1. Откройте **Перемещение (QR)** и создайте документ: **склад → бар**.
2. Нажмите **Сформировать список (FIFO)** — система подберёт товары по принципу «самые старые UUID».
3. При необходимости корректируйте список:
   - Можно **удалить** предложенные позиции из списка.
   - Можно **добавить** произвольные позиции, отсканировав `ITM:...`.
4. Переходите к отбору на складе и **сканируйте** товары:
   - Скан `ITM` → помечает товар как **in_transit**.
   - Скан `BOX` (sealed) → добавляет все товары коробки.
   - Если нужна частичная отгрузка из sealed коробки — она **автоматически открывается** и нужные товары выводятся из коробки.
5. Нажмите **Отгрузить**.
6. В баре сканируйте `ITM`/`BOX` для приёмки:
   - Статус → **in_stock**, локация → **bar**.
7. Нажмите **Закрыть**:
   - Все **непринятые** товары будут списаны как **lost_in_transit**.

## Инвентаризация (QR)

1. Откройте **Инвентаризация (QR)** и выберите локацию.
2. Нажмите **Создать**, затем **Старт** — система сформирует **ожидаемый список** всех товаров в локации.
3. Идите по складу и **сканируйте**:
   - `ITM` — конкретная бутылка.
   - `BOX` (sealed) — засчитывает все товары в коробке.
4. Нажмите **Закрыть**:
   - Все **не найденные** товары будут списаны как **lost** с причиной **missing_inventory**.

## Автоматическая упаковка в коробки (приёмка)

Доступно на страницах:
- **Приёмка (QR)** (создание документа),
- **Редактирование приёмки**.

Запускается после `Сгенерировать` (статус документа `generated`/`posted`).

### Поля формы и назначение

| Поле | Для чего используется |
|------|------------------------|
| **Количество в коробке** | Сколько `product_item` положить в одну коробку в текущем запуске. |
| **Лимит коробок (опц)** | Ограничивает, сколько коробок создать за один запуск. Полезно, когда нужно сначала упаковать часть товара в один формат коробки, а остаток — в другой формат. Если не заполнено — лимита нет. |
| **Товар (опц)** | Упаковывать только выбранный `product_id`; если не выбран — все товары документа. |
| **Lot ID (опц)** | Упаковывать только выбранный `lot_id` (должен принадлежать этой приёмке). |
| **Создавать неполную коробку** | Если включено, остаток меньше размера коробки тоже попадёт в коробку. |
| **Полные коробки закрывать** | Если включено, коробки с полным количеством будут `sealed=true`; неполные остаются открытыми. |

### Результат запуска

После нажатия **Автосоздать коробки** показываются:
- **Создано коробок** (`boxes_created`),
- **Упаковано бутылок** (`items_packed`),
- **Осталось без коробки** (`items_remaining_unboxed`),
- список QR созданных коробок.

### Как поддерживаются коробки разного размера

Запускайте автоупаковку несколько раз:
1. Первый запуск, например `Количество в коробке=12`, `Лимит коробок=10`.
2. Второй запуск для остатка, например `Количество в коробке=6`.
3. Третий запуск для хвоста, например `Количество в коробке=1` с неполной коробкой.

## Просмотр перемещений и история конкретного item

### Список перемещений

В **Список перемещений (QR)** добавлена кнопка **Просмотр**:
- открывает страницу со списком конкретных `product_item` в выбранном документе;
- отображает:
  - дату создания перемещения,
  - дату отгрузки (`picked_at`),
  - дату приёмки (`received_at`),
  - статус перемещения и состояние позиции.

Строки непринятых (утерянных в пути) подсвечиваются бледно-красным.

### История конкретного item

На странице просмотра перемещения и в **Список единиц (QR)** есть кнопка **История**.

Страница истории item показывает:
- **Сводку по товару**:
  - `product_item_id`, `product_item_qr_code`,
  - текущий статус и локацию item,
  - `product_id`, название, SKU,
  - `lot_id`,
  - текущую базовую стоимость продукта,
  - сумму покупки конкретного item.
- **Остатки по товару** по локациям (`stock`).
- **Историю перемещений** этого item с датами и статусами (утерянные строки подсвечиваются).

> Текущее ограничение: в модели нет отдельной себестоимости на уровне `product_item`, поэтому поле «Сумма покупки item» рассчитывается из текущего `product.base_cost`.

## Новые API (кратко)

### Приёмка
- `POST /api/v1/receipts/{receipt_id}/auto-box`  
  Автоматически создаёт коробки и распределяет по ним неупакованные `product_item` этой приёмки.

### Перемещения
- `GET /api/v1/transfers/{transfer_doc_id}/items`  
  Возвращает список item конкретного перемещения с датами создания/отгрузки/приёмки и флагом потери.

### Единицы (QR)
- `GET /api/v1/scan/items/{product_item_id}/history`  
  Возвращает полную историю конкретного item: сводка, остатки, перемещения.
