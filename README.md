# Порядок действий (QR)

Ниже описаны рабочие процессы для новых разделов меню: **Приёмка (QR)**, **Перемещение (QR)**, **Инвентаризация (QR)**.  
Во всех процессах **QR содержит только тип и UUID** (`ITM:{uuid}`, `BOX:{uuid}`), все связи — по `id`.

---

## Приёмка (QR)

1. Откройте **Приёмка (QR)** и выберите склад (локацию).
2. Нажмите **Создать** — создаётся документ приёмки.
3. Добавьте строку: **товар + количество** (базовая единица).  
   Дополнительно можно указать номер партии поставщика.
4. Нажмите **Сгенерировать** — создаются **партия (lot)** и **единицы товара (product_item)**.
5. Нажмите **Печать этикеток ITM** — распечатайте и наклейте QR на бутылки.
6. (Опционально) Сформируйте коробки вручную:
   - Отсканируйте любую бутылку `ITM:...` для контекста (product/lot/location).
   - Нажмите **Создать коробку** (создаётся открытая коробка).
   - Сканируйте `ITM:...` и добавляйте товары в коробку.
   - Нажмите **Закрыть (seal)** и распечатайте QR коробки (**QR коробки**).
7. (Опционально) Сформируйте коробки автоматически в блоке **Автоматическая упаковка в коробки**.
8. Нажмите **Подтвердить** — приёмка зафиксирована.  
   **Отменить** — погасит сгенерированные единицы (void).

## Перемещение (QR)

> Механика похожа на приёмку, **но партия не создаётся**.

1. Откройте **Перемещение (QR)** и создайте документ: **склад → бар**.
2. Нажмите **Сформировать список (FIFO)** — система подберёт товары по принципу «самые старые UUID».
3. При необходимости корректируйте список:
   - Можно **удалить** предложенные позиции из списка.
   - Можно **добавить** произвольные позиции, отсканировав `ITM:...`.
4. Переходите к отбору на складе и **сканируйте** товары:
   - Скан `ITM` → помечает товар как **in_transit**.
   - Скан `BOX` (sealed) → добавляет все товары коробки.
   - Если нужна частичная отгрузка из sealed коробки — она **автоматически открывается** и нужные товары выводятся из коробки.
5. Нажмите **Отгрузить**.
6. В баре сканируйте `ITM`/`BOX` для приёмки:
   - Статус → **in_stock**, локация → **bar**.
7. Нажмите **Закрыть**:
   - Все **непринятые** товары будут списаны как **lost_in_transit**.

---

## Инвентаризация (QR)

1. Откройте **Инвентаризация (QR)** и выберите локацию.
2. Нажмите **Создать**, затем **Старт** — система сформирует **ожидаемый список** всех товаров в локации.
3. Идите по складу и **сканируйте**:
   - `ITM` — конкретная бутылка.
   - `BOX` (sealed) — засчитывает все товары в коробке.
4. Нажмите **Закрыть**:
   - Все **не найденные** товары будут списаны как **lost** с причиной **missing_inventory**.

## Автоматическая упаковка в коробки (приёмка)

Доступно на страницах:
- **Приёмка (QR)** (создание документа),
- **Редактирование приёмки**.

Запускается после `Сгенерировать` (статус документа `generated`/`posted`).

### Поля формы и назначение

| Поле | Для чего используется |
|------|------------------------|
| **Количество в коробке** | Сколько `product_item` положить в одну коробку в текущем запуске. |
| **Лимит коробок (опц)** | Ограничивает, сколько коробок создать за один запуск. Полезно, когда нужно сначала упаковать часть товара в один формат коробки, а остаток — в другой формат. Если не заполнено — лимита нет. |
| **Товар (опц)** | Упаковывать только выбранный `product_id`; если не выбран — все товары документа. |
| **Lot ID (опц)** | Упаковывать только выбранный `lot_id` (должен принадлежать этой приёмке). |
| **Создавать неполную коробку** | Если включено, остаток меньше размера коробки тоже попадёт в коробку. |
| **Полные коробки закрывать** | Если включено, коробки с полным количеством будут `sealed=true`; неполные остаются открытыми. |

### Результат запуска

После нажатия **Автосоздать коробки** показываются:
- **Создано коробок** (`boxes_created`),
- **Упаковано бутылок** (`items_packed`),
- **Осталось без коробки** (`items_remaining_unboxed`),
- список QR созданных коробок.

### Как поддерживаются коробки разного размера

Запускайте автоупаковку несколько раз:
1. Первый запуск, например `Количество в коробке=12`, `Лимит коробок=10`.
2. Второй запуск для остатка, например `Количество в коробке=6`.
3. Третий запуск для хвоста, например `Количество в коробке=1` с неполной коробкой.

## Просмотр перемещений и история конкретного item

### Список перемещений

В **Список перемещений (QR)** добавлена кнопка **Просмотр**:
- открывает страницу со списком конкретных `product_item` в выбранном документе;
- отображает:
  - дату создания перемещения,
  - дату отгрузки (`picked_at`),
  - дату приёмки (`received_at`),
  - статус перемещения и состояние позиции.

Строки непринятых (утерянных в пути) подсвечиваются бледно-красным.

### История конкретного item

На странице просмотра перемещения и в **Список единиц (QR)** есть кнопка **История**.

Страница истории item показывает:
- **Сводку по товару**:
  - `product_item_id`, `product_item_qr_code`,
  - текущий статус и локацию item,
  - `product_id`, название, SKU,
  - `lot_id`,
  - текущую базовую стоимость продукта,
  - сумму покупки конкретного item.
- **Остатки по товару** по локациям (`stock`).
- **Историю перемещений** этого item с датами и статусами (утерянные строки подсвечиваются).

> Текущее ограничение: в модели нет отдельной себестоимости на уровне `product_item`, поэтому поле «Сумма покупки item» рассчитывается из текущего `product.base_cost`.

## Что изменено (актуально)

1. Добавлен единый checkout продаж:
   - продажа по названию товара;
   - продажа по `ITM` QR (конкретный item);
   - продажа по `BOX` QR (только целиком);
   - продажа бокалов с поддержкой конкретного item или авто-выбора FIFO.
2. Добавлен учёт количества в коробке:
   - поле `box.quantity` хранит текущее число item в коробке;
   - поле обновляется при упаковке, распаковке, продаже, потерях, перемещениях.
3. Добавлен учёт разлива по бокалам:
   - таблица `product_item_pour` хранит остаток бокалов по конкретному `product_item`.
4. Перемещения по FIFO доработаны:
   - сначала подбираются полные `sealed` коробки (если подходят по количеству),
   - затем добор поштучно FIFO.
5. Частично разлитые item не участвуют в перемещениях и продаже целой коробкой/бутылкой.
6. Цена продажи берётся из `price_list`, при отсутствии — из `product.base_cost`.
7. Добавлен интерфейс управления прайсами с историей ревизий и файловыми калькуляторами.
8. В прайс попадают только товары, которые **сейчас в наличии** в выбранной локации (`stock.quantity > 0`).
9. Добавлены юниты на уровне типа товара:
   - `product_type_unit` хранит дефолтные юниты типа;
   - в `product_type.strict_units_by_type` можно включить строгий режим;
   - при создании/обновлении товара юниты автоматически подставляются из типа, если в payload юниты не переданы.

## Продажи (единый интерфейс)

1. Откройте раздел **Продажи**.
2. Добавьте позиции в корзину одним или несколькими способами:
   - **По товару**: товар + количество + юнит;
   - **По QR единицы**: `ITM:...`;
   - **По QR коробки**: `BOX:...` (количество фиксировано = 1 коробка);
   - **По бокалам**: товар + количество бокалов (+ опционально `ITM` конкретной бутылки).
3. Нажмите **Оформить продажу**.
4. Система:
   - спишет агрегированный остаток и/или конкретные `product_item`;
   - обновит состояние коробок (`quantity`, открытие/изъятие при необходимости);
   - сформирует и отправит обычный HTTP-запрос на `/api/v1/sales/register-sales-transactions`;
   - вернёт итог с расшифровкой проданных строк.

### Правила для бокалов

- Если передан `item_qr_code`, бокалы списываются с этого конкретного item.
- Если `item_qr_code` не передан, система берёт первый доступный item по FIFO.
- Когда бутылка исчерпана по бокалам, item переводится в `sold`.

### Как настроить составной товар из дробных частей (пример: бутерброд)

Цель: продавать **целый** товар `Бутерброд`, который списывает **доли** других товаров.

1. Создайте товары-ингредиенты (обычные, не составные):
   - `Багет` (базовая единица, например `baguette`),
   - `Томатная паста` (базовая единица, например `jar`).
2. Для каждого ингредиента задайте дробную связь в разделе **Дробные части**:
   - для `Багет`: крупная единица = базовая, дробная = `slice`, дробных в 1 крупной = `10` (ratio `0.10`);
   - для `Томатная паста`: крупная единица = базовая, дробная = `20ml`, дробных в 1 крупной = `10` (ratio `0.10`).
3. Создайте товар `Бутерброд` как **составной** (тип товара с `is_composite=true`).
4. В компонентах `Бутерброда` добавьте:
   - `Багет`, количество `0.10`,
   - `Томатная паста`, количество `0.10`.
5. При продаже `Бутерброда` система рекурсивно раскладывает состав до листовых ингредиентов и списывает их FIFO, включая сериализованные `product_item` по дробям.

Важно:
- Количество в компоненте сейчас задаётся в базовой единице компонента (поэтому `0.10` означает 10% базовой единицы).
- Для вложенных составов (например, дегустационный набор, включающий другие составные товары) списание также идёт рекурсивно до конечных ингредиентов.
- Если для ингредиента нет корректной конверсии долей (product/type units), продажа вернёт ошибку конверсии.

## Управление прайсами

1. Откройте раздел **Прайсы**.
2. Выберите локацию, для которой формируется прайс.
3. Создайте ревизию одним из режимов:
   - **Процент на все товары** (пример: `+5%`);
   - **Фиксированная добавка** (пример: `+10` в валюте);
   - **Версионированный расчёт** (`calculator_version_id` + `calculator_params` JSON).
4. После создания:
   - значения записываются в текущий `price_list`;
   - сохраняется полная история в `price_list_revision` и `price_list_revision_item`.

### Важные правила

- Прайс создаётся только для товаров с остатком в локации (`stock.quantity > 0`).
- При запросе текущего прайса возвращается **последняя ревизия** для локации.
- Если ревизий нет, отдаются текущие строки `price_list`, также только для товаров в наличии.
- Для режима расчёта сохраняется снапшот:
  - название расчёта,
  - версия,
  - hash исходника (`SHA256`).
- Если на фронте выбран устаревший `calculator_version_id`, backend делает fallback по `calculator_file + calculator_class`.

### Версии расчётов

- Калькуляторы лежат в `backend_full/app/pricing_calculators`.
- Каждый калькулятор — класс-наследник `BasePriceCalculator`.
- Для каждого класса задаются метаданные:
  - `calculator_code`,
  - `calculator_name`,
  - `calculator_version`,
  - `changelog`.
- Примеры версий:
  - `backend_full/app/pricing_calculators/example_multiplier.py` → `example_multiplier`, `Example Multiplier`, `1.0.0`;
  - `backend_full/app/pricing_calculators/example_multiplier_v2.py` → `example_multiplier`, `Example Multiplier`, `1.1.0`.
- При каждом запросе списка калькуляторов backend синхронизирует файловые версии в БД.
- В UI поле **Параметры (JSON)** валидируется, при ошибке парсинга показывается человекочитаемая подсказка.

## Изменения в данных

| Сущность | Поле | Назначение |
|---------|------|------------|
| `box` | `quantity` | Текущее количество `product_item` в коробке. |
| `product_item_pour` | `product_item_id` | Ссылка на конкретный item. |
| `product_item_pour` | `glasses_total` | Сколько бокалов в полной бутылке (для item). |
| `product_item_pour` | `glasses_sold` | Сколько бокалов уже продано из item. |
| `price_list_revision` | `location_id`, `mode`, `percent_delta`, `amount_delta`, `calculator_file`, `calculator_class`, `calculator_params` | Заголовок ревизии прайса и параметры пересчёта. |
| `price_list_revision` | `calculator_version_id` | Версия расчёта, использованная для ревизии. |
| `price_list_revision` | `calculator_name_snapshot`, `calculator_version_snapshot`, `calculator_source_hash_snapshot` | Снапшот метаданных расчёта на момент пересчёта. |
| `price_list_revision_item` | `revision_id`, `product_id`, `unit_id`, `previous_amount`, `amount` | Строки ревизии с историей значений до/после. |
| `price_calculator` | `code`, `name`, `description`, `is_active` | Реестр логических расчётов. |
| `price_calculator_version` | `calculator_id`, `version`, `file_path`, `class_name`, `source_hash`, `changelog`, `is_active` | Версии реализаций расчётов. |

## Новые API (кратко)

### Приёмка
- `POST /api/v1/receipts/{receipt_id}/auto-box`  
  Автоматически создаёт коробки и распределяет по ним неупакованные `product_item` этой приёмки.

### Перемещения
- `GET /api/v1/transfers/{transfer_doc_id}/items`  
  Возвращает список item конкретного перемещения с датами создания/отгрузки/приёмки и флагом потери.

### Единицы (QR)
- `GET /api/v1/scan/items/{product_item_id}/history`  
  Возвращает полную историю конкретного item: сводка, остатки, перемещения.

### Продажи
- `POST /api/v1/simple-catalog/sales/checkout`  
  Единый checkout продаж (товар / `ITM` / `BOX` / бокалы), с отправкой итогового payload в `/api/v1/sales/register-sales-transactions`.

### Прайсы
- `GET /api/v1/simple-catalog/prices/calculators`  
  Список доступных версий расчётов (`version_id`, `calculator_code`, `calculator_name`, `calculator_version`, `source_hash`, `file`, `class_name`).
- `POST /api/v1/simple-catalog/prices/revisions`  
  Создать новую ревизию прайса для локации и применить её к текущим ценам.  
  Для `mode=calculator` используйте `calculator_version_id` (основной путь).
- `GET /api/v1/simple-catalog/prices/revisions`  
  История ревизий прайса (с фильтром по локации).
- `GET /api/v1/simple-catalog/prices/revisions/{revision_id}`  
  Детальный состав конкретной ревизии + метаданные версии расчёта.
- `GET /api/v1/simple-catalog/prices/current?location_id=...`  
  Текущий прайс локации (последняя ревизия) + метаданные версии расчёта.
